# Metadata packs

Eddy's generated segment models know an element's name, position, CLR type and the validation rules
in `Validate()`. They do not know the standard's data element number, the formal data type (ID, AN,
N0, R, DT, TM), or what a code value means. Metadata packs supply that missing layer as data files,
so the models never have to be regenerated and licensed content can be kept out of the repository.

Two sources combine at runtime through `Eddy.Core.Metadata.MetadataCatalog`:

1. **Derived metadata** (`DerivedSegmentMetadata.Describe(Type)`), computed from a model type: the
   `[Position]` properties give positions and names, the CLR type gives a coarse data type, and
   probing `Validate()` gives required flags, min/max lengths and date/time formats. Always available,
   never needs data files.
2. **Packs** (`MetadataPack`), JSON files that overlay data element numbers, formal types, code lists
   and better names. A pack can be partial: a pack that only holds code lists is valid.

`MetadataCatalog.Describe(Type)` returns a `SegmentDefinition` that starts from the derived data and
applies every loaded pack for the same standard and version (nearest lower version when there is no
exact match). Pack values win over derived values where both exist.

## Provenance and licensing

- EDIFACT packs in `metadata/packs/` are generated from the MIT-licensed BizTalk EDIFACT schemas
  published by Microsoft (github.com/microsoft/Integration). They contain names, data element
  numbers, types, lengths and code values. They do not contain code descriptions.
- X12 has no freely licensed source with broad coverage. X12 packs are not bundled. Users can
  import their own licensed tables with the metadata tool (see below) and load them at runtime.
- Any pack records its `provenance` and `license` fields; keep them accurate.

## File format

One JSON object per file. Keys are case sensitive. Every section is optional except `format`,
`standard` and `version`.

```json
{
  "format": "eddy-metadata-pack/1",
  "standard": "EDIFACT",
  "version": "D96A",
  "name": "EDIFACT D96A from BizTalk schemas",
  "provenance": "Generated by Eddy.MetadataTool import-biztalk from microsoft/Integration commit abc123",
  "license": "MIT (Microsoft Corporation)",

  "dataElements": {
    "3035": { "name": "Party qualifier", "type": "ID", "min": 1, "max": 3 },
    "3036": { "name": "Party name", "type": "AN", "min": 1, "max": 35 }
  },

  "composites": {
    "C082": {
      "name": "Party identification details",
      "elements": [
        { "pos": 1, "de": "3039", "req": "M" },
        { "pos": 2, "de": "1131", "req": "C" }
      ]
    }
  },

  "segments": {
    "NAD": {
      "name": "Name and address",
      "elements": [
        { "pos": 1, "de": "3035", "req": "M" },
        { "pos": 2, "composite": "C082", "req": "C" },
        { "pos": 6, "de": "3164", "req": "C" }
      ]
    }
  },

  "codes": {
    "3035": { "BY": "Buyer", "SU": "Supplier", "DP": "" }
  }
}
```

Field rules:

- `standard`: `X12` or `EDIFACT`.
- `version`: X12 uses the six digit GS08 form (`004010`); EDIFACT uses the directory name (`D96A`).
  `MetadataCatalog` normalises `4010` and `00401` to `004010`.
- `dataElements.<number>.type`: one of `ID`, `AN`, `N`, `N0`..`N9`, `R`, `DT`, `TM`, `B`. `N` alone
  means an integer with no implied decimals; `N2` means two implied decimals.
- `min` / `max`: character lengths. Omit when unknown.
- `segments.<id>.elements[].pos`: 1-based element position, the same number as the `[Position]`
  attribute. Positions may be sparse; unlisted positions keep their derived metadata.
- `de` names a data element; `composite` names an entry in `composites`. Exactly one of the two.
- `req`: `M` mandatory, `O` optional, `C` conditional. Omit when unknown.
- `codes.<number>`: map of code value to description. An empty description is allowed and means the
  value is known to be valid but no text is available.

## Tool

`tools/Eddy.MetadataTool` is a console app:

    dotnet run --project tools/Eddy.MetadataTool -- derive    --standard X12 --version 004010 --out x12-004010.derived.json
    dotnet run --project tools/Eddy.MetadataTool -- import-biztalk --dir <folder of EFACT_D96A_*.xsd> --out metadata/packs/edifact-D96A.json
    dotnet run --project tools/Eddy.MetadataTool -- import-codes --standard X12 --version 004010 --csv codes.csv --out my-codes.json
    dotnet run --project tools/Eddy.MetadataTool -- merge a.json b.json --out merged.json
    dotnet run --project tools/Eddy.MetadataTool -- gen-codes --pack a.json [--pack b.json ...] --namespace <ns> --out <dir> [--enums]

`import-codes` reads a CSV with the header `dataElement,code,description`. `derive` writes what the
library computes from the models so it can be inspected or hand-edited into a pack. `gen-codes` is
covered below.

## Generated code lists

A pack's `codes` sections can also be turned into C# source: `gen-codes` writes one
`Eddy.Core.Codes.CodeList` subclass per data element that has codes, across as many packs as you give
it (later packs fill in a description an earlier one left blank, but never overwrite one that's
already there). The class is named from the data element's `dataElements.<number>.name`
(`PartyQualifierCodes` for EDIFACT 3035's "Party qualifier"; `EntityIdentifierCodes`, not
`EntityIdentifierCodeCodes`, for X12 98's "Entity Identifier Code" - a trailing "Code" folds into the
"Codes" suffix instead of doubling) and holds a `public const string` per code, plus - with `--enums`,
and only for a data element that has at least one non-empty description - a nested enum whose members
carry `[CodeValue("...")]` so `Code<TList>` can convert to and from them:

    dotnet run --project tools/Eddy.MetadataTool -- gen-codes --pack metadata/packs/edifact-D96A.json --namespace Eddy.Edifact.Codes.D96A --out Eddy.Edifact.Codes/D96A --enums

Every generated file carries the source pack(s)' `provenance` and `license` in its header comment.
`Eddy.Core.Codes.Code<TList>` (`TList` being one of these generated classes) is the value type a
generated model property uses to carry such an element around; see Readme.Md, "Code lists".

## Loading packs

    var catalog = new MetadataCatalog();
    catalog.AddPack(MetadataPack.Load("metadata/packs/edifact-D96A.json"));
    catalog.AddPacksFromDirectory("/path/to/packs");
    var definition = catalog.Describe(typeof(Eddy.Edifact.Models.D96A.NAD_NameAndAddress));

Eddy Notepad loads every pack embedded in the application, then every `*.json` file in the directory
named by the `EDDY_METADATA_PACKS` environment variable, then anything opened through
File > Load Metadata Pack.
